# Data strategy / 从失败到生产

## 能力地图与配比

桌面指令先要识别对象和属性，再理解关系、计数与组合条件，最后输出可执行的对象集合。原始评测集对六类任务均衡采样（各 40 条），避免总分由最多的任务主导；此配比只是覆盖型诊断，不是线上流量估计。开发/保留在 scene family 层面预先隔离。增强池会有意偏向重要失败，不能与原始均衡测试集直接混合汇报“准确率提升”。

## 优先级公式

对符合条件的开发集失败样本 i：

`P_i = q_i × (0.30 f_i + 0.25 t_i + 0.20 s_i + 0.15 n_i + 0.10 r_i) / c_i`

| 变量 | 可复算定义 | 假设与局限 |
|---|---|---|
| f | 该任务 dev 失败数 / 该任务 dev 样本数 | 覆盖受当前生成器与模型影响，不是线上失败频率 |
| t | configs/demo.json 的任务重要性 | 产品假设；对象选择/组合指令权重最高，应由真实风险与任务价值校准 |
| s | 失败类型的严重程度权重 | 目前同类错误同权；不代表真实机器人的伤害概率 |
| n | 1 / 同 signature 的 dev 样本数 | signature=任务+难度+query 属性+关系；只是重复度代理 |
| r | 有历史版本时：历史正确、当前失败为 1 | 默认只有首轮，全部为 0；可传 previous 进行真实回归排序 |
| q | 合成标签验证通过为 1.0 | 不等于人工复核置信度 |
| c | 1.0 + 0.1×物体数 | 相对生产工作量代理，不是美元或人工小时 |

所有权重、任务价值、严重性、预算、signature 上限、成本系数均在配置中。不能用未经校准的模型自报置信度排序，所以默认 confidence=null，不进入评分。`priority_queue.jsonl` 保留每个变量与最终得分。

排序后先按分数降序、ID 升序稳定排序，再施加最多 18 个父样本、每 signature 最多 2 个、同 scene family 最多 1 个。避免一个热门模板挤占全部预算。不是最优背包算法：它便于审计，小规模足够；大规模时应加入真实成本、相似度和组合覆盖约束。

系统/API 错误、格式错误、拒答先转工程/Prompt 队列；歧义与标签错误先转数据修复，不自动进入训练样本生产。数据格式正确不意味着其标签值得训练，人工复核可以阻止回流。

## 生产策略

| Operator | 如何生产 | 必须验证 |
|---|---|---|
| counterfactual | 单属性替换或单关系 token 变化 | 标准答案确实变化；无重复 |
| hard_negative | 加入仅有关键条件不符的相似物体 | ID 与条件可区分；重新计算标签 |
| curriculum | 保持原 query，增加物体使场景更复杂 | 不宣称已验证“更难”；控制难度变量 |
| attribute_substitution | 全局替换颜色并同步替换 query | 答案等变保持，避免颜色记忆 |
| spatial_perturbation | 小幅改变物体中心 | 重新判定关系，边界样本不能继承旧标签 |
| distractor_injection | 增加非原目标物体 | 不遮挡、不越界、重新检查答案 |

每个选中父样本尝试六个算子。每个算子最多 8 次去重重试，失败明确记录；不为了凑数量放入重复或无效样本。默认实际接受 108 条，即 18×6。标签由 oracle 重新生成，手写单元测试与视觉抽检补充检查共同逻辑错误。

## 数据清洗、版本与隐私

检查 schema、内容指纹、图片字节 hash、命名路径、唯一 ID、对象间距、oracle 标签、family split 和跨集同图。固定 Python/Pillow 版本可复现 PNG 字节；不同渲染器版本不能假定图像 hash 不变。数据源全为自建，不含公司/学校/个人文件。真实 API 仅 opt-in 发送这些合成图像和问题；原始输出与缓存仍需作为可能含敏感内容的本地材料审查，默认 `reports/local` 与 `.cache-api` 不入 Git。

版本记录内容 hash、配置 hash、代码 Git commit 与 environment.json；所有增强记录 parent_id、family、operator、标签是否变化。更新模板或标签语义必须更新版本并重跑基线，不能借用旧分数。

## 回流与停止条件

产品确认优化目标 → 评测定位 dev 错误 → 专家复核标签/根因 → 预算排序 → 数据工程生产/去重 → 抽检验收 → 算法团队训练小样本消融 → 独立 holdout 与安全切片回归 → 决定继续、修复或终止。

当前代码实现到生产与规则回归，**不实现训练**。下一轮真实实验用等数量随机增强作对照、相同训练预算、多个随机种子、冻结 holdout 和任务成功率，比较 targeted 与 random 的增量效益。

当错误主要来自坏标签/API、同模板收益饱和、重要切片恶化、单位新增合格样本成本失控，或新增数据不能在预注册独立测试上带来可信收益时，应暂停扩量，先改问题定义或管线。停止阈值由试点预算和错误代价设定，不能用当前规则对照的百分点倒推训练收益。
