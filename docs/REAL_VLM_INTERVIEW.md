# 面试：真实 VLM 评测与数据闭环

30 秒回答：我将一个 metadata 规则流程演示升级为图像加问题驱动的本地 VLM 实验。先冻结场景族隔离协议，再用相同图片配对比较两种提示，保留失败分母、原始文本与格式指标。真实错误进入人工复核队列，只有开发集失败可以生成可追溯样本。没有训练，所以不会把增强数量或提示差异包装成训练收益。

工程主线：数据合同 → 泄漏审计 → 版本冻结 → 图像推理 → 严格评分 → 失败复核 → 开发集生产 → 独立验证。必须掌握分母、配对、分组、版本和症状/根因；进阶是跨域数据、校准、多种子训练对照；暂时不需要分布式训练或复杂 Agent。

五个思维模型：

1. 信息隔离：让被测系统只拿到部署时可见输入。因为额外标签会改变问题本身。适合防泄漏审计；接口隔离不能替代安全沙箱，面试要说清边界。
2. 配对实验：同图比较减少样本难度差异。适合提示或预处理对照；共享场景的问题并不独立，统计单位应是场景族。
3. 全分母可靠性：异常也是系统交付能力的一部分。只在成功请求上报准确率会高估；工程上同时报告系统错误和格式合法性。
4. 因果克制：答错是症状，不能直接证明 OCR、视觉或推理错误。需要遮挡、重标、图像替换等干预；面试应提出可检验诊断而非猜原因。
5. 血缘与不变性：增强必须解释什么变了、标签为何仍成立。平移可保持相对关系，裁剪不一定；追踪父样本和版本才可复盘污染。

三个争议及选择：

- 有限答案解码能否算能力提升？支持者强调生产协议合法性；质疑者指出约束会改变答案先验。两者适用目标不同；应拆开格式与语义指标。本轮不使用约束解码。
- 合成集能否代表真实能力？支持者看重可控标签与反例；质疑者强调纹理、遮挡、相机域差异。本轮只能验证小型合成分布，不声称真实任务收益。
- 错误驱动采样是否优于随机采样？支持者认为能集中稀缺预算；反方指出偏差与多样性坍缩。尚未训练时无证据选择赢家；需未来等预算随机对照和独立测试。

常见错误回答：“生成增强后能力提高了”“格式合法就是理解正确”“族隔离证明没有全部泄漏”“总分高就应该发布”。本项目旧规则候选总体提高但计数退化被 REJECT，正好说明最后一种错误。

工程检查：固定 revision 与环境；图像哈希；输入字段白名单；族和近重复检查；推理前冻结；无漏行/重复行；异常不缓存；原始输出留存；人工根因 pending；增强父族只来自 dev；公开 CI 与本地推理证据分开。

最小实践：从 review_queue 找一个 dev 失败，先写出可观察症状，再提出两个竞争根因与能区分二者的实验。不要修改 holdout 或立即宣称根因。
