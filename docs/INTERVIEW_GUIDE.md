# Interview guide / 可迁移的项目理解框架

## 30 秒介绍

我做了一个面向具身 VLM 的数据策略验证平台，把模型评测、失败归因、样本优先级、针对性数据生产和版本回归串成可复现闭环。它生成 240 条桌面多模态样本，并从开发集选出 18 个父样本，生产 108 条增强数据。最重要的是，它能在总分上涨时识别计数退化并拒绝候选版本。目前使用明确标注的离线规则对照验证工程流程，没有把结果包装成真实大模型训练提升。

## 2 分钟介绍

这个岗位的核心不是做聊天界面，而是把模型优化需求转化为可执行的数据策略。我从具身任务中“选错对象”这一类问题出发，把它拆为空间关系、属性绑定、计数、目标选择、多条件指令和反事实六类能力。

数据由 Python/Pillow 程序化生成，样本同时保存图像、结构化场景、问题、答案、任务标签、难度、split 和版本哈希。相关反事实变体按场景族一起切分，开发集只负责发现问题和生产数据，保留集只做版本回归。

评测不仅输出准确率，还保留原始输出、解析错误、系统错误、延迟、分层指标和按场景族 bootstrap 的置信区间。自动失败分类是待复核假设，不是从一个错答案就断言模型视觉坏了。生产队列根据失败频率、任务重要性、严重性、新颖度与成本打分，并用多样性约束防止重复模板挤占预算。

真实运行生成了 240 条原始样本、108 条增强数据。规则 v2 的保留集总分从 41.7% 升到 90.3%，但计数从 100% 降到 41.7%，因此门禁拒绝它。这些是预设规则缺陷的对照结果，不是训练收益。下一步应接入只看图像和问题的真实 VLM，并在固定训练预算下比较针对性数据和等量随机数据，使用新的独立测试集检验是否迁移。

## STAR（按真实范围）

- **Situation:** 为模型训练策略产品岗位建立可验证作品，展示如何从模型错误制定数据策略；不是虚构公司需求或线上用户反馈。
- **Task:** 交付无 API Key 可运行、指标可追溯且能发现回归的端到端系统。
- **Action:** 定义能力与数据合同；设计 family split；实现生成器/adapter/评测；构建可解释队列和六类增强；补充人工复核接口、回归门禁、Dashboard、测试和版本历史。
- **Result:** 从运行报告引用样本数、增强数、具体切片与拒绝决策；展示代码、测试与截图。GitHub 发布状态按实际远程可访问性陈述。

## 十个追问与回答框架

| 追问 | 回答框架 | 容易犯的错误 |
|---|---|---|
| 1. 没有训练，为什么叫数据飞轮？ | 已实现评测→策略→生产→回归；训练是可接入的下一阶段；现阶段验证 workflow | 把 reference v2 当微调模型 |
| 2. 为什么 240 条够用？ | 足够验证工程和覆盖；不足以估计真实泛化；报告 n、families、CI 与域边界 | 把样本量小解释为统计高效 |
| 3. 如何防泄漏？ | family 切分、内容/图像 hash、dev-only selection、holdout冻结；新实验换未公开集 | 只随机切行、不管近重复 |
| 4. 如何知道是感知还是推理错？ | 最终错答不能区分；先查图和标签，再做属性/关系分解与配对干预 | 凭 task_type 给出确定根因 |
| 5. 为什么这种优先级权重？ | 产品初始假设；展示每个变量；用真实标注成本/任务风险和消融校准 | 声称是学出来或最优权重 |
| 6. 反事实和 hard negative 有何不同？ | 前者最小干预验证依赖；后者构造近似但不匹配条件的候选；检查标签变化 | 修改图片却沿用标签 |
| 7. 总分大涨为什么拒绝？ | 平均数可遮掩关键切片；说明计数负控与零容差 guardrail；统计CI不替代产品底线 | 只展示总准确率 |
| 8. 如何证明数据策略有效？ | 固定模型/预算，targeted vs equal-size random vs no-data，多 seed，独立 holdout 与真实任务 | 用增强集上的分数当泛化证据 |
| 9. 如何接真实 VLM？ | image+question 接口、env key、模型快照、超时重试缓存、成本与原始输出；不发送 metadata | 把 MockTransport 测试说成 API 实验 |
| 10. 如何推进跨团队落地？ | 产品定目标/停止条件；算法训练消融；数据工程版本去重；运营质量/仲裁；RACI | 声称协作过不存在的团队 |

## 五个核心思维模型

| 模型 | 为什么成立/适用 | 失效边界 | 面试与工作怎么用 |
|---|---|---|---|
| 测量先于优化 | 优化方向来自可定义能力与可靠标签 | 指标与真实任务脱节时会优化错目标 | 先说目标、分母、切片和真实任务关联 |
| 错误是症状，干预才接近因果 | 同一个错答有多种根因，单因素对照排除部分解释 | 合成干预不自然/多个属性同时变动 | 设计最小反例与诊断 probe |
| 数据预算是约束优化 | 候选样本价值、冗余和成本不同 | 权重未经校准或相似度代理失真 | 展示评分分解与多样性约束，保留随机探索 |
| 评测独立性是资源 | 调参会消耗测试集新鲜度 | 已公开测试集无法恢复为秘密证据 | 划分 dev/holdout，预注册，新增保留集 |
| 发布是多目标决策 | 总体收益与重要能力风险可能冲突 | 过严门禁可能对小样本噪声过敏 | 明确重要切片、容差、置信度和回滚条件 |

## 三个核心争议与选择边界

1. **合成数据还是自然数据？** 合成派强调可控、标注成本低和反事实覆盖；自然派强调真实分布。前者最强证据应是固定预算消融后的独立任务收益，后者最强证据应是跨域失败分析；本项目都未测得。共同底线是不能只看训练/合成集分数。当前用合成验证工程，未来混入合法真实场景并单独报域外表现。
2. **困难样本优先还是代表性采样？** 前者假设难例信息量高，后者担心标签噪声、分布偏移和灾难性遗忘。应比较同预算数据选择对照，不存在本仓库证明的普遍最优比例。当前优先级队列受多样性约束，正式训练还应保留代表性 replay 与随机探索。
3. **严格自动答案还是 LLM Judge？** 自动判分可重复、便宜，但对开放答案不够灵活；Judge 覆盖广但可能偏好自己的模型、位置和表达风格。有限答案优先透明 oracle；开放任务应先做人类校准、盲评和重测。当前没有 Judge，也没有校准成绩。

## 工程检查清单与最小实践

先复现 README；打开一个计数回归样本手算标准答案；只修改一项 priority 权重，把新结果写到 `reports/local`；解释选中父样本如何变化。随后修复 v2 的 large-only 计数缺陷，在新版本中检查全能力回归。这个练习验证你理解代码与决策，不应写成真实模型训练。

讲解顺序：数据与任务合同 → 评测/分母/标签 → 失败与优先级 → 增强/独立验证 → 真实模型扩展。必须掌握前四项；微调消融是进阶；分布式训练框架与云基础设施暂时可忽略。

## 不能夸大

不能说训练/微调过 VLM、提高真实机器人成功率、服务了线上用户、节省公司成本、完成供应商合作、拥有真实世界模型实验。可以说“实现并测试了数据策略与评测闭环，生成并验证了合成数据，用预设规则对照证明回归门禁有效”。如果代码由 AI 协助完成，应如实说明，并能现场解释、修改与复现关键模块。
