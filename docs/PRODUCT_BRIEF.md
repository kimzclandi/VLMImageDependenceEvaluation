# Product brief / 产品定义

## 用户、场景与问题

面向模型训练策略产品经理、评测工程师与数据运营负责人。当用户反馈“抓错对象”时，总准确率无法直接告诉团队该改视觉识别、组合条件、Prompt 格式还是数据标签。这个项目把问题拆成可测试能力，产出带证据的下一轮数据生产队列，以及是否允许发布的回归决策。

最小场景是二维桌面物体选择。它连接具身任务的感知与指令理解，但不执行机械臂控制，不代表真实抓取成功率。

## 输入、输出与主流程

输入：固定随机种子的原始程序化图像、机器可验证的场景/query、模型适配器、任务权重与生产预算。

输出：逐样本预测、分层指标与区间、待复核错误、排序及其理由、108 条默认增强样本、可追溯实验报告与候选版本门禁。

业务用户可以在 Dashboard 从“总分上涨”追到“计数下降”的具体样本，再查看应该生产什么数据。开发集决定生产，保留集决定是否上线，两者不能混用。

## 成功指标与验收

| 层次 | 成功定义 | 当前证据 |
|---|---|---|
| 数据可信度 | schema、图片哈希、可见物体与标签一致；跨 split 同图为 0 | validation.json 与数据测试 |
| 评测可信度 | 所有样本纳入分母；输出与内容哈希一一对应 | v1/v2_scores.jsonl |
| 决策可解释性 | 每条优先级能展开变量；预算与多样性约束可复算 | priority_queue.jsonl |
| 回归有效性 | 能在总体上升时拦截预设计数退化 | holdout_regression.gate = REJECT |
| 可复现性 | 相同环境与配置重建相同数据、预测与决策 | scripts/check_reproducibility.py |
| 工程可用性 | 无 API Key 完成闭环；Dashboard 可启动、可切换 | 单元/端到端/AppTest 与浏览器截图 |

企业环境真正要优化的指标应是经产品确认的任务成功率、单位有效数据成本、回流周期、重要切片质量及安全失败率；本项目不提供这些线上数值。

## 产品取舍

选择轻量 Python + JSONL + Pillow + Streamlit，因为目前最有价值的是可追溯决策，不是数据库、消息队列或复杂 Agent。规则 reference 是已知缺陷的测试工具，可以验证门禁是否有效；真实 VLM 接口与离线默认路径分开。没有加入 LLM Judge，短答案可直接机器判定，加入第二个模型反而增加不透明误差。

## 非目标

不追求 SOTA，不实现基础模型预训练或微调，不声称真实模型能力提升，不做世界模型仿真、三维动力学、ROS 控制、真机实验、供应商采购或线上业务收益验证。

## 风险与范围

图像简单且 ID 可见，可能形成捷径；程序 oracle 与渲染器共享结构可能产生共同错误；holdout 很小且公开后会泄漏。用独立手写测试与人工视觉检查降低风险，但不能消除。真实应用前需要重新冻结未公开测试集、增加人工标注和摄像头数据，并预注册实验与发布标准。
