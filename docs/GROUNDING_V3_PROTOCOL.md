# 视觉贡献验证 v3：实验边界与复现

研究问题不是“换提示能否涨分”，而是“同一模型正确回答是否依赖真实图像”。第一轮提示比较未超过多数答案先验，因此本轮只验证证据有效性，不训练或搜索提示。

## 事前设计

`2c48e99` 保存推理前代码、数据和协议。`reports/grounding_v3/protocol.json` 冻结每个模型/处理器文件 SHA-256、四个执行源文件、依赖版本、完整提示、CPU float32/eager/4 threads、greedy/16 tokens、配对规则与停止条件。权重仍为第一轮固定的 SmolVLM-256M revision。

30 个场景族，dev/holdout 各 15 族、45 题。每个集合：计数 5 族 × 5 个答案（0–4），存在与空间各 5 族 × 2 个答案。每族共享布局的全部反事实在同一集合内。没有文字、字母 ID、图像文件名或标签进入模型输入；问题在同任务内恒定，因此不能靠题面区分答案。文件名是随机种子和场景身份的摘要，适配器仅接收解码后的像素与问题。

计数与存在题始终四个对象，避免对象总量充当答案。空间题是唯一红圆与蓝方，按中心 x 坐标定义左右，中心相隔至少 200 像素，不使用同列微小坐标差。存在题对红色对象的形状做反事实变更；计数题改变四圆中的红色数量。干净二维图形并不代表道路视觉复杂度。

每题真实图、白底空白图、错配图三个干预共 270 次生成。错配图是同一场景族中答案不同的另一变体，问题完全相同；候选和随机种子全部事前保存，不能意外包含原正确场景。所有组都按原题原 gold 评分；donor gold 另用于诊断，不能替换主评分目标。

主指标是保留集三任务等权宏平均的真实−空白差。全题准确率也必须报告，但计数占 25/45，因此不作为唯一比较。开发集多数答案先验按字典序打破平局（0/no/no），保留集全题 1/3、任务宏平均 0.4。格式严格匹配完整回答，系统错误、无结果及格式非法不剔除。

2,000 次按任务分层的场景族配对 bootstrap，同族全部变体一起抽取。每个任务仅五个保留族，区间非常粗，不能外推至开放世界。正向贡献判据预设为真实−空白宏平均区间下界 >0，且真实优于错配；输出改变次数只是敏感性，不能替代正确率提升。

## 去重范围

检查所有图像 SHA-256、同族 split、一对多派生关系、错配 gold 反转。跨集合逐对计算 RGB 平均绝对差，低于 0.002 拒绝运行。该检查能阻止几乎相同像素，但不能证明语义模板独立；两个集合有意共用生成器，因此只检验同分布合成任务。

## 复现与恢复

从仓库根目录，复用独立 `.venv-vlm`，不修改 `.venv`。固定快照路径由操作者提供；无付费 API 或联网推理。

```bash
PYTHONPATH=src .venv-vlm/bin/python -m flywheel.grounding run --snapshot /path/to/fixed/snapshot
.venv/bin/python scripts/verify_grounding.py
.venv/bin/python -m pytest -q
.venv/bin/streamlit run dashboard.py --server.port 8513
```

参考结果是不可覆盖证据。每个原始生成独立原子写入；进程锁防止双运行器，恢复核对身份并跳过已记录的观测。首段只跑三条后恢复，不重新采样或覆盖。系统错误被保留为本次固定实验的失败观测，而不是可复用的成功推理缓存；如果需要重试错误，应新建明确的后续实验，不能静默更换本轮分母。

如希望从零重推，应在独立 checkout 中把整个结果目录移至另一个保留位置，仅保留原协议，再运行。不要删除第一轮 `reports/real_vlm`、`data/visual_v2` 或覆盖已有 `reports/qa.json`。脚本的 `--freeze` 仅用于新版本初始生成；已经冻结的版本拒绝再次冻结。

## 从失败到生产决策

`dev_failures.json` 分开记录可观察症状、三个竞争解释、对应图像干预结果和未验证状态。若无视觉增益，不应据此机械增加平移样本：可能是模型能力、提示理解或表征问题。格式错误路由到接口/格式检查，系统错误路由基础设施，不能直接排入补标队列。所有记录保持“待人工复核”，不声称根因已证实。

同样大小的圆意味着红色像素面积与计数相关；即使视觉干预有效，也无法区分“真正逐对象计数”和“颜色面积捷径”。固定颜色、少量布局与共享模板进一步限制组合泛化结论。本轮不根据结果修改这些设计，而是如实保留其适用范围。
